# Requirements Document: モバイルナビゲーションメニュー

## Introduction

現在、スマートフォン画面ではナビゲーションリンク（Coffee）とユーザーメニュー（プロフィール、ログアウト）が非表示となっており、ユーザーがコーヒー一覧ページやプロフィールページに移動できない重大なUX問題が発生しています。この機能は、ハンバーガーメニューを実装し、小画面デバイスでも完全なナビゲーション機能を提供することで、この問題を解決します。

レスポンシブデザインはSimple Coffee Collectionsの重要な原則であり、「あらゆるデバイスから快適にアクセスできる体験を提供する」というプロダクトビジョンを実現するために不可欠です。

## Alignment with Product Vision

**Product Principle: "レスポンシブデザイン"**
- ターゲットユーザーは「スマートフォン、タブレット、デスクトップなど様々なデバイスからアクセスしたい」というニーズを持っています
- 技術要件として「320px - 2560px viewport widths」をサポートすることが定められています
- 現在の実装では小画面（<640px）でナビゲーションが利用できず、プロダクト原則に違反しています

この機能により、すべてのデバイスサイズで一貫したナビゲーション体験が提供され、ユーザーエンゲージメントとデータ品質の向上が期待できます。

## Requirements

### Requirement 1: ハンバーガーメニューボタンの表示

**User Story:** モバイルユーザーとして、小画面デバイスでメニューアイコンを見たい。これにより、ナビゲーションオプションが利用可能であることが視覚的にわかるため。

#### Acceptance Criteria

1. WHEN viewport幅が640px未満の場合 THEN ヘッダー右側にハンバーガーメニューアイコンボタンを表示すること
2. WHEN viewport幅が640px以上の場合 THEN ハンバーガーメニューアイコンボタンを非表示にすること
3. WHEN メニューが閉じている場合 THEN 3本線のハンバーガーアイコン（☰）を表示すること
4. WHEN メニューが開いている場合 THEN 閉じるアイコン（×）を表示すること
5. WHEN ハンバーガーメニューボタンにフォーカスした場合 THEN アクセシビリティのため視覚的なフォーカス状態を表示すること

### Requirement 2: メニューの開閉機能

**User Story:** モバイルユーザーとして、ハンバーガーメニューをタップしてナビゲーションメニューを開閉したい。これにより、必要な時にナビゲーションオプションにアクセスできるため。

#### Acceptance Criteria

1. WHEN ハンバーガーメニューボタンをクリックした場合 THEN メニューが開閉すること
2. WHEN メニューが開いた場合 THEN メニュー内のナビゲーションリンクとユーザーメニューを表示すること
3. WHEN メニュー内のリンクをクリックした場合 THEN ページ遷移後、メニューを自動的に閉じること
4. WHEN メニューが開いている状態でページをスクロールした場合 THEN メニューが画面に固定されず、自然にスクロールすること
5. IF メニューが開いている場合 THEN ボタンのaria-expanded属性がtrueであること

### Requirement 3: ナビゲーションリンクの表示

**User Story:** モバイルユーザーとして、メニュー内でコーヒー一覧ページへのリンクを見たい。これにより、自分の記録したコーヒー評価を閲覧できるため。

#### Acceptance Criteria

1. WHEN メニューが開いた場合 THEN 「Coffee」リンクを表示すること
2. WHEN 現在のページが /coffee で始まる場合 THEN 「Coffee」リンクにアクティブ状態のスタイルを適用すること（bg-amber-100 text-amber-800）
3. WHEN リンクにフォーカスした場合 THEN ホバー状態のスタイル（bg-gray-100）を適用すること
4. WHEN リンクをタップした場合 THEN 対応するページに遷移し、メニューを閉じること

### Requirement 4: ユーザーメニューの表示

**User Story:** ログインユーザーとして、メニュー内でプロフィールページとログアウト機能にアクセスしたい。これにより、アカウント管理ができるため。

#### Acceptance Criteria

1. WHEN ユーザーがログインしている場合 THEN メニュー内に「プロフィール」リンクと「ログアウト」ボタンを表示すること
2. WHEN ユーザーがログインしていない場合 THEN ユーザーメニューセクションを表示しないこと
3. WHEN ユーザーメニューが表示される場合 THEN ナビゲーションリンクとの間に視覚的な区切り（border-top）を追加すること
4. WHEN 「プロフィール」リンクをタップした場合 THEN /profile ページに遷移し、メニューを閉じること
5. WHEN 「ログアウト」ボタンをタップした場合 THEN ログアウト処理を実行すること

## Non-Functional Requirements

### Code Architecture and Modularity
- **Single Responsibility Principle**: NavBarコンポーネントはナビゲーション表示とメニュー開閉状態の管理のみを担当する
- **Modular Design**: メニューの状態管理にReact hooksを使用し、再利用可能な設計とする
- **Dependency Management**: 既存のLogoutButtonコンポーネントを再利用し、新たな依存関係を最小限にする
- **Clear Interfaces**: NavBarPropsインターフェースを拡張せず、既存のuserEmail propsのみで動作する

### Performance
- メニューの開閉アニメーションは60fps以上のフレームレートを維持すること
- メニューの状態変更によるレンダリングは、NavBarコンポーネント内に限定すること
- 不要なre-renderを避けるため、useCallbackやuseMemoを適切に使用すること

### Security
- メニュー内のリンクやボタンは、既存の認証・認可機構を継承すること
- XSS攻撃を防ぐため、ユーザー入力（userEmail）を適切にエスケープすること

### Reliability
- メニューの開閉状態が意図せずリセットされないこと
- JavaScriptが無効な環境でも、主要なナビゲーションリンクにアクセス可能であること（Progressive Enhancement）

### Usability
- タッチターゲットサイズは最低44x44pxを確保すること（iOS/Androidガイドライン準拠）
- メニューのアニメーションは、prefers-reduced-motionメディアクエリに対応すること
- メニューが開いている状態を視覚的に明確に示すこと（アイコンの変化、aria-expanded属性）
- キーボード操作（Tab、Enter、Escape）でメニューを操作可能にすること
- スクリーンリーダーがメニューの状態を適切に読み上げられるよう、aria属性を設定すること

### Testing (TDD Requirements)

**Test-Driven Development (TDD) アプローチ**を採用し、すべての機能要件に対してテストファーストで実装すること。

#### テスト戦略

1. **Red-Green-Refactor サイクル**:
   - **Red**: 機能要件に対応する失敗するテストを先に書く
   - **Green**: テストをパスする最小限の実装を行う
   - **Refactor**: テストをパスした状態で、コードを改善する

2. **テストファイル構成**:
   - コンポーネントテスト: `app/(app)/_components/__tests__/nav-bar.test.tsx`
   - テストライブラリ: Jest + React Testing Library
   - モック: `@testing-library/user-event` でユーザーインタラクションを再現

3. **テストカバレッジ目標**:
   - Statement Coverage: 90%以上
   - Branch Coverage: 85%以上
   - Function Coverage: 90%以上
   - すべての受け入れ基準に対応するテストケースを作成すること

#### テストケース要件

各要件（Requirement 1-4）に対して、以下のテストを実装すること：

**Requirement 1: ハンバーガーメニューボタンの表示**
- [ ] 小画面（<640px）でハンバーガーメニューボタンが表示されること
- [ ] 大画面（≥640px）でハンバーガーメニューボタンが非表示になること
- [ ] メニュー閉じ状態でハンバーガーアイコンが表示されること
- [ ] メニュー開き状態で閉じるアイコンが表示されること
- [ ] フォーカス時に視覚的なフォーカス状態が表示されること

**Requirement 2: メニューの開閉機能**
- [ ] ハンバーガーメニューボタンクリックでメニューが開閉すること
- [ ] メニュー開き時にナビゲーションリンクとユーザーメニューが表示されること
- [ ] メニュー内リンククリック後にメニューが閉じること
- [ ] aria-expanded属性がメニュー開閉状態に応じて更新されること

**Requirement 3: ナビゲーションリンクの表示**
- [ ] メニュー開き時に「Coffee」リンクが表示されること
- [ ] 現在のページが /coffee の場合、アクティブ状態のスタイルが適用されること
- [ ] リンクフォーカス時にホバー状態のスタイルが適用されること
- [ ] リンククリック時にページ遷移し、メニューが閉じること

**Requirement 4: ユーザーメニューの表示**
- [ ] ログインユーザーの場合、プロフィールリンクとログアウトボタンが表示されること
- [ ] 未ログインユーザーの場合、ユーザーメニューが表示されないこと
- [ ] ユーザーメニューとナビゲーションリンク間に視覚的な区切りがあること
- [ ] プロフィールリンククリック時に /profile に遷移し、メニューが閉じること
- [ ] ログアウトボタンクリック時にログアウト処理が実行されること

#### テスト実装の順序

1. **Phase 1**: ハンバーガーメニューボタンの表示テスト（Requirement 1）
2. **Phase 2**: メニューの開閉機能テスト（Requirement 2）
3. **Phase 3**: ナビゲーションリンクの表示テスト（Requirement 3）
4. **Phase 4**: ユーザーメニューの表示テスト（Requirement 4）

各フェーズで、Red → Green → Refactor サイクルを完了してから次のフェーズに進むこと。

#### テストツール要件

- **Jest**: テストランナーとアサーション
- **React Testing Library**: コンポーネントレンダリングとクエリ
- **@testing-library/user-event**: ユーザーインタラクションシミュレーション
- **jest-dom**: カスタムDOMマッチャー（toBeInTheDocument, toHaveAttribute等）
- **モック戦略**:
  - `next/navigation` の usePathname をモック
  - `@/components/LogoutButton` をモック
  - viewport サイズのシミュレーション（window.matchMedia）
